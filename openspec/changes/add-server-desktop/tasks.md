## 1. Prerequisites and spike

- [x] 1.1 Confirm the prerequisite behaviour is on `main`: a release declares shared-temporary-directory safety and the installer renders its unit without `PrivateTmp=`. Verified by `scripts/build-standalone-server-artifact.mjs` writing `sharedTmpSafe: true`, `apps/terminay-cli/src/unit.ts` omitting the line for such a release, and the live system-scope unit on the development host having no `PrivateTmp=` line. The spec side, archiving `daemon-restart-keeps-terminals-usable` (itself waiting on `terminals-survive-restart`), is a merge-order requirement checked in 7.4, not a gate on the spike.
- [x] 1.2 Run the display-server spike in three configurations: Debian 13 and Debian 12 under a unit rendered by the installer, as an unprivileged account with no login session, and the official image. Record commands and output in `openspec/adr/evidence/server-desktop-spike.md`. Every lettered item must pass in every configuration; a failure leaves this task unticked until `design.md` and ADR-0145 are revised (by a superseding ADR if needed) and the item passes on a re-run. (a) `Xtigervnc` with `-rfbport -1 -rfbunixpath -nolisten tcp` has zero TCP/UDP listeners in `ss -lntup`. (b) A second unprivileged account is refused on both the X display and the RFB socket; whether an abstract X socket exists is recorded. (c) With the display server denied network access, by a network namespace or by a seccomp launcher, a cookie-holding X client still connects, a `vncconfig -connect` reverse connection fails, and a program on the display still reaches the network. The mechanism that works is recorded per configuration. (d) A controller and a view-only viewer connected at once with the two credentials: the viewer's input is refused by the display server, and whether the viewer's connection is sent clipboard messages is recorded for both TigerVNC versions. (e) Closing a connection that holds a key and a pointer button leaves neither held, checked on the display itself. (f) `SetDesktopSize` resizes the screen. (g) The XFCE session starts with a private D-Bus and runtime directory and no TCP listener. (h) A separately installed graphical fixture (`xterm` or `x11-apps`) renders and takes input. (i) The display, session, and fixture survive a restart of the server unit, with the X socket and lock file still present. (j) Installing the package set enables or starts no service. Verified by the evidence file showing a pass with output for every lettered item in every configuration.

## 4. Server desktop service

- [x] 4.1 Implement host support detection (Linux, `os-release` ID `debian`, shared temporary directory, a working network-denial mechanism), required-program checks made on status requests and on Check again without polling, and the status state machine, publishing changes only to connections that pass the desktop authority check. Verified by unit tests for each state and reason with fixture `os-release` files, a private-temp fixture, and a no-denial-mechanism fixture, and a test that a narrowed connection receives no status event.
- [x] 4.2 Implement desktop authority: `write` or `admin`, no narrowing claims, MCP principals refused, per-read and per-write revalidation, close on revocation. Verified by tests for an ordinary paired-device connection (allowed), project-scoped, session-scoped, and MCP-principal connections (forbidden without revealing state), and a revoked device (stream closed).
- [x] 4.3 Implement the desktop holder: a detached process that takes the kernel-held lock, generates the cookie and the two VNC passwords (owner-only files, never in argv or logs), chooses the display number (765 preferred, collision scan), starts `Xtigervnc` per ADR-0145 through the seccomp launcher, starts the shared session with no extra services, and serves a versioned control socket at a derived path with the session holder's credential handshake. Verified by an integration test on Linux asserting no TCP/UDP listener, a failed reverse connection, a fixture program on the display still reaching the network, owner-only modes on every desktop file except the X socket and its lock file, and a foreign display on 765 left untouched.
- [x] 4.4 Implement adopt-or-start in the server: derive the socket path, attempt the handshake, start a holder only when the lock is free, report `failed` when the lock is held by a holder that cannot be spoken to, replace a holder whose protocol version is incompatible, and restart a crashed display on the same number and cookie while closing open streams. Verified by integration tests for a server restart with a fixture program running (same display, same program pid), an upgrade to a compatible release (program keeps running), an incompatible holder version (desktop restarted, interruption reported), a killed display server (restarted on the same number), a planted state file naming another process (not adopted, signalled, or connected to), a process that holds the lock without the secret (not adopted, `failed`), and a stale socket after a reboot (cleaned up, new holder).
- [x] 4.5 Implement `enable` and `disable`, with the stop reaching the holder through the handshake, the open-windows confirmation signal, and setup not starting a desktop that is off. Keep the state out of the generic settings operations. Verified by tests that disable leaves no holder, session, or display server and no window, that the state is `off`, that a generic settings write does not change it, and that setup completing while off starts nothing.
- [x] 4.6 Implement the unix-socket connector with VNC challenge authentication and the stream operations: single controller, serialized takeover that confirms the old upstream connection closed before opening the new one, and `server.desktop.control` events naming the device. Verified by tests for second-opener view-only, take control, two simultaneous takeovers (exactly one controller), forged input on a view-only stream, the event reaching every connection showing the desktop, and the shared relay's negative-access and clipboard tests from 2.5 and 2.9 run against this connector.
- [x] 4.7 Add the per-launch baseline provider to the launch resolver, consulted before the profile overlay, returning the display environment only while the desktop runs and never where the server process has `DISPLAY` or `WAYLAND_DISPLAY`. Verified by launch-resolver tests for the baseline, a profile override and null, desktop off, a desktop started after the server, a server with its own display, and a launch through a session holder that outlived a server restart.
