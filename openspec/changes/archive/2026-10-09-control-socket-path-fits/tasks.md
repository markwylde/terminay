## 1. Placement

- [x] 1.1 Add a pure resolver beside the control endpoint (`apps/terminay-server/src/mcp/controlSocketPlacement.ts`) that takes the data directory, the platform, the runtime directory and the temporary directory and returns the socket's placement (path, and whether it is in the data directory or a runtime directory) or a typed failure with the candidate paths, their byte lengths and the limit. It uses `socketPathFits` and the limit from `packages/server-core/src/sessionHolder/paths.ts`. Verified by a new unit test covering: a path that fits stays in the data directory; one that does not goes to `<runtime>/terminay-<12 hex>/control.sock`; the same data directory gives the same path twice and two data directories give two paths; `XDG_RUNTIME_DIR` is preferred when absolute and ignored when relative; a multi-byte data directory within the limit in characters and over it in bytes goes to the runtime directory; a runtime candidate that is also too long yields the failure with both lengths; Windows returns the named pipe.
- [x] 1.2 Add the runtime directory check: create it `0700` when absent, and otherwise require a directory that is not a symbolic link, is owned by the process's user, and has no group or other permission bits, returning the reason when one fails and changing nothing on disk. Verified by a unit test on a temporary directory for each of: absent (created `0700`), ours and closed (accepted), a symbolic link (refused, link untouched), a regular file (refused), mode `0755` (refused and still `0755` afterwards), and by a case with an injected owner id that differs from the process's (refused).
- [x] 1.3 Make the control endpoint leave a runtime directory's permissions alone: its `chmod(parent, 0o700)` applies to a data directory placement only. Verified by a unit test that starts an endpoint on a runtime placement whose directory is `0700` and finds it listening with the socket at `0600`, and by the existing `apps/terminay-server/test/control-endpoint.test.mjs` passing.

## 2. Desktop

- [x] 2.1 In `electron/main.ts`, have both `startMcpControlEndpoint` and `getTerminalControlEnv` take the socket's address from the resolver, with the terminal's address available before the endpoint starts, removing `getMcpControlSocketPath`. Verified by `npm run lint`, the TypeScript build, and `grep -n "getMcpControlSocketPath" electron` returning nothing.
- [x] 2.2 Map a placement failure and a refused runtime directory to the launch recovery message the spec gives (data directory path, socket path length, the limit, the remedy, and the refused directory with its reason), ahead of the general message, and have Desktop diagnostics record them. Verified by a unit test of the message builder for both causes asserting each fact is present and that the text contains no token, and by the end-to-end refusal test finding the message and the reason in the diagnostics folder.
- [x] 2.3 Cover a long data directory end to end: start Desktop with `TERMINAY_USER_DATA_DIR` at a path whose control socket would exceed the limit, and assert the workspace opens, the terminal's `TERMINAY_CONTROL_SOCKET` names a path outside the data directory and within the limit, and its parent directory is mode `0700`. Verified by a new test in `e2e/` passing under `npm run test:e2e`.
- [x] 2.4 Cover the address surviving a relaunch: with the same long data directory, relaunch Desktop and assert the terminal environment names the same socket path as before. Verified by the same end-to-end spec.
- [x] 2.5 Cover the refusal end to end: pre-create the runtime directory with mode `0755`, start Desktop with the long data directory, and assert the recovery state names that directory and says why, and that the directory's mode is unchanged. Verified by the same end-to-end spec.
