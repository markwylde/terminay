## 2. Workflow records, lifetime and durability (server-core)

- [x] 2.1 Add `workflowStore.ts`: one canonical file per terminal session, named by the session id and holding its workflow or none, written synchronously with ADR-0088 durable replacement (`.previous` kept) before a change is acknowledged or published. Replace and remove are a single replace of that file, and the file is deleted when the session ends. Verified by a test that a change is on disk before its acknowledgement resolves, and by crash-injection tests at every step of a W1→W2 replacement (temp write, flush, `.previous` copy, rename) proving exactly one of W1 or W2 restores.
- [x] 2.2 Roll back a change whose write fails and fail the request with `internal`. Verified by a test with an injected write failure: the step keeps its earlier status and nothing is published.
- [x] 2.3 Restore after held sessions are reattached. Restore workflows of running sessions and discard the rest. Set aside a corrupt file with a corrupt marker and fall back to `.previous`. With no valid copy, mark the session named by the file as unrestorable (persisting across restarts until removed) and never invent steps. Verified by store tests for a running session (restored), a closed one (discarded), a corrupt file with a valid `.previous` (restored from it, corrupt file kept aside), and two held sessions with only one session's copies both corrupt (only that session unrestorable, the other restored, still unrestorable after a second restart).
- [x] 2.4 Keep workflow files on a shutdown that leaves sessions in the holder, and delete them on terminal close or session end. Verified by tests that shut down with a held session (file kept) and close the terminal (file deleted, not restored).
- [x] 2.5 Implement the step status rules: free transitions, at most one `running`/`needs_input`, `step_active` naming the active step's id, note replace/clear/keep, `step_not_found`, and the unfinished predicate. Verified by unit tests for each scenario in "Step status rules".
- [x] 2.6 Implement the step-time table (start and retry into either `running` or `needs_input` from `not_started`, `done` and `failed`, moves between `running` and `needs_input` keeping both times, direct completion, repeated final status, reset) and the resume point. Verified by unit tests for every row of the table in design.md and both resume-point scenarios.
- [x] 2.7 End a workflow when its terminal closes, keep it on a project move, and add the user-initiated remove command (also used for an unrestorable workflow). Verified by server tests for close, `panel.move`, and remove.
- [x] 2.8 Publish workflow changes to clients that can see the terminal, and include workflows in the snapshot a fresh client receives. Verified by a protocol test where a second client receives a step update and a client outside the project receives nothing.
