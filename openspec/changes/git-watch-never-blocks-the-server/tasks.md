## 2. Linux tree watcher (`packages/server-core/src/gitService/treeWatch.ts`)

- [x] 2.1 A work queue (a set of paths) drained one step per `setImmediate`, with separate per-step limits: 512 directory entries read through `fs.promises.opendir` (a wide directory resumes across steps), 64 `fs.watch` calls, and one filter call of at most 64 candidates. Verified by the wide-directory and many-directories lag tests in 2.8.
- [x] 2.2 Arm-then-list: open a directory's watch, then list it, enqueue child directories that are neither watched nor excluded, and report one change for the directory. Verified by the "new directory then file" test.
- [x] 2.3 Event classification (design Decision 2): excluded names are dropped; watched children are `lstat`ed and compared on `dev`/`ino`; unknown names are `lstat`ed, so files deliver, directories go through the filter, and ENOENT delivers; `null` names deliver `null`. Verified by tests for an ignored `dist/` delete/recreate (no change delivered), a deleted untracked file (delivered), and a replaced directory (re-armed).
- [x] 2.4 Removal vs failure (Decision 3): close a subtree only on ENOENT/ENOTDIR or a `dev`/`ino` change; fail the whole watch through `onError` on a child watcher error or close while its directory exists, an unexpected fs error, a filter rejection, or loss of the root. Verified by tests for a populated rename (old subtree closed, new path observed), a subtree deletion (watch count back to baseline), and an injected child-watcher error (whole watch fails once).
- [x] 2.5 Nested repositories (Decision 6): a listed non-root directory containing a `.git` entry is closed and recorded as excluded, and no path inside it reaches the filter. Verified by a test with a real submodule-like nested repository.
- [x] 2.6 `refilter(kind)` (Decision 5): bump a generation that discards stale filter results; re-check the excluded set, and for `rules` re-check the watched directories, all in bounded steps. Verified by un-ignore and newly-ignore tests.
- [x] 2.7 Ceiling and capacity (Decision 8): `MAX_WATCHED_DIRECTORIES` 16,384 (injectable); exceeding it fails with code `ETOOMANYDIRS` naming the ceiling; `ENOSPC`/`EMFILE` from `fs.watch` fail with their codes. Verified by a ceiling-of-8 test and an injected `fs.watch` that throws each code.
- [x] 2.8 Teardown (Decision 9): `close()` and any failure abort a controller checked after every await and before every `fs.watch`, filter call and callback; the filter receives the signal. Verified by a test that closes during the initial scan with a slow filter and asserts no later watch, callback or filter call.
- [x] 2.9 Tests in `packages/server-core/test/git-tree-watcher.test.mjs`. Event-independent cases run on every OS through platform injection. Event-driven cases run on Linux only: elsewhere per-directory `fs.watch` is not inotify, and production builds watches only on Linux. The tests cover: the cases named in 2.2–2.8, plus lag tests (3,000 directories created at once, and one directory of 30,000 files) asserting a 50 ms interval never fires more than 250 ms late. Verified by the file passing.

## 3. Wiring

- [x] 3.1 `NodeGitStateWatcher` uses `TreeWatch` for `recursive: true` on Linux and the native recursive watch elsewhere, with the platform injectable. Verified by the existing `git-node-watcher.test.mjs` passing with the tree watch forced on.
- [x] 3.2 Working-tree filter in `service.ts`: drop `.git` and other registered worktree roots, then run `git -c core.quotePath=false check-ignore -- <paths>` (≤64 paths as arguments; `-z` needs `--stdin`, which the runner lacks) through the bounded `runGit` with the watch's signal; exit 0 parses the line-separated ignored paths, unquoting C-quoted lines, exit 1 means none, and anything else (other exit, spawn failure, truncation, an unexpected path) rejects. Verified by service tests against a real repository with ignored `node_modules/` and `dist/`, and by an injected-runner test for each rejection.
- [x] 3.3 Git-directory filter: drop top-level `INERT_GIT_DIR_ENTRIES` except `info`, plus `refs/tags`, `refs/stash`, and inert entries under `worktrees/<name>/`. Verified by a unit test of the filter and by the commit/branch-switch watcher tests.
- [x] 3.4 Call `refilter('rules')` on a repository's working-tree handles for a working-tree `.gitignore` leaf, or a Git-directory `info/exclude` or `config` change, and `refilter('tracking')` for `index`. Verified by the un-ignore service test and a test that `git add -f` on an ignored directory leads to it being watched.
- [x] 3.5 On Linux, give every worktree root its own working-tree watch instead of collapsing nested roots; keep the collapse for native watches. Verified by a test with a linked worktree under an ignored `.claude/worktrees/` whose save is attributed to that worktree.
