## 3. Folder roots and worktree folders

- [x] 3.1 Implement `FolderRootResolver` per ADR-0050: confirm project ownership, confirm the link against the maintained worktree listing, canonicalize once, fail closed with a typed error; wire it into both hosts. Verified by `packages/server-core/test/folder-roots.test.mjs` (a foreign folder, an unregistered, prunable or bare worktree, a missing path, a symlinked replacement, one listing read per resolution), and by `apps/terminay-server/test/folders.test.mjs` and `scripts/server-terminal-authority-folders.test.mjs` against a real Git service. The resolver reads the Git service's maintained listing and starts no process of its own; there is no separate spawn-count assertion.
- [ ] 3.2 Add optional `folderId` to file, Git status and changes, and Git action requests, and thread the resolved root through each operation. Verified by adapter tests that list and mutate inside a linked folder's worktree while `project.root` is unchanged, and by the existing root-replacement test still failing closed. Progress: the catalog adapter (list, preview, tasks, create, rename, delete) takes `folderId` and resolves its scope per operation (`fileService/folderScope.ts`, `test/file-catalog-folder-scope.test.mjs`). Still to do: the file session, content, and observation adapters; both hosts supplying `folderScope`; and the client request types. Git requests already target a worktree by id and need no folder parameter.
- [x] 3.3 Stop issuing `project.root.update` from file and Git operations, and remove the switch-project-root action and its handlers. Verified by a grep finding no caller outside the deliberate project-root setting, and by the cross-worktree tests rewritten to select a folder.
- [x] 3.4 Implement `FolderReconciler` on the existing worktree listing: create a linked folder per unfoldered worktree, move panels to General and remove the folder when a worktree disappears, hold passes during a Terminay move and rewrite the link, and ignore Git changes that cannot affect folders. Verified by `packages/server-core/test/folder-reconciler.test.mjs` (12 tests), `git-worktree-removed-scope.test.mjs`, `git-worktree-move-adapter.test.mjs`, and both hosts' folder tests, one of which asserts no timer, interval, or watcher is created.
- [x] 3.5 Extend the launch intent with `folderId`, make `TerminalLaunchResolver` fall back to the folder root and ignore an active panel from another folder, and place the new panel in that folder. Verified by `terminal-launch-resolver.test.mjs` (first terminal in a linked folder, an active panel in another folder, a missing worktree, a foreign folder) and `terminal-folder-placement.test.mjs` through the composed server, including a failed spawn leaving nothing behind.
- [x] 3.6 Make MCP `open_terminal` and `split_terminal` create in the caller's folder, and workspace-scope `open_terminal` create in General. Verified by `apps/terminay-server/test/folders.test.mjs` for the standalone adapter, including `list_terminals` across folders. The Desktop MCP handlers pass the folder through and are checked by source assertion only; nothing runs them.

## 6. Capture

- [x] 6.1 Add the server setting **Move terminals into new worktree folders**, default on, through classification, defaults, the renderer key set, and a settings field. Verified by settings normalisation tests and the field appearing in the settings UI. Progress: classified and defaulted on the server and read by both hosts. Still to do: the renderer key set and settings field.
- [x] 6.2 Open the server's Git event socket at a short runtime path, add the Trace2 variables and a per-session token to the launch environment unless the terminal already sets its own target, and turn a `worktree add` start event into "this terminal created this worktree". Verified by `packages/server-core/test/worktree-capture.test.mjs` (real Git under a shell carrying the variables, an unknown token, an over-long line, a pre-set target left alone, 100,000 events leaving about 0.2 MB behind in a separate process with a collectable heap) and `terminal-git-command-env.test.mjs` (a launched terminal carries the variables with its own token and gives the token up when it ends).
- [x] 6.3 Implement the process lookup: when a worktree appears and Git reported nobody, read the process table once, find the running `git worktree add` for that directory, and walk its parents to a terminal's shell. Verified by `worktree-capture.test.mjs`: the parent walk from a recorded process table, two terminals at once naming nobody, and exactly one table read per lookup. There is no integration test that wins the race against a real Git; the spike measured that separately.
- [x] 6.4 Record `createdByPanelId` on the folder, ignore worktrees present when the project was bound, and move nobody when no terminal is established. Verified by `folder-reconciler.test.mjs` (a worktree already there never asks; a later one records its creator; a vanished creator still gets a folder) and `worktree-capture-end-to-end.test.mjs` (a worktree added outside every terminal moves nobody).

Verified by an E2E in which a scripted command in a terminal adds a worktree and changes into it, the terminal moves, and Undo returns it for good. Progress: the server moves the terminal and appends a `folder.terminal-captured` event scoped to the project (`worktree-capture-end-to-end.test.mjs`). Still to do: the notice with Undo in the renderer.
- [ ] 6.6 With the setting off, write the capture offer on the folder and render Move it here and Not now beneath it on every device. Verified by a two-client test that accepting or declining on one clears it on the other. Progress: the server writes the offer and accepts or declines it (`workspace-folders.test.mjs`, `worktree-capture-end-to-end.test.mjs`); the tree component renders it. Still to do: a two-client test.
